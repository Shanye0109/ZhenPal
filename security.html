更新日期：2026-11-17

适用范围：本次静态演示站点、模块化源码，以及后续接入真实业务时必须补齐的服务端边界。

1. 本次交付的安全边界

当前交付是可以本地打开、上传到静态托管服务的前端演示。页面中展示的是虚构业务记录；真实账号、订单、发票、收货地址和供应商成本尚未接入。前端已经建立安全渲染、输入校验、受限的界面偏好恢复和模块边界；这些措施不能替代登录认证、公司隔离或业务数据库备份。

本文件中的“当前实现”指源码中可审查的前端措施；“发布验收”指还要对最终构建产物执行的检查；“生产化要求”指未来后端工作，不表示已经上线。构建命令、备份位置和最终验收结果分别见根目录 README、DESIGN 和随包测试记录。

能力当前静态前端生产化要求
页面文本与链接使用安全 DOM 工具；链接采用允许范围；不把动态业务文本当作 HTML 执行。继续保留前端措施；后端也按字段和用途验证数据。
账号与公司权限后台、客户入口及样例数据分别打包；没有真实登录。服务端身份认证、公司归属、对象与操作授权、会话撤销。

导入与导出界面偏好 JSON 恢复、当前演示数据 CSV 导出。业务导入需预检、权限、事务、错误报告；敏感导出需字段和公司范围授权。
发票与附件页面展示与流程预留；没有真实发票上传或 OCR。私有文件存储、类型与内容校验、访问授权、扫描与 OCR 处理边界。
业务更新只演示状态和页面关系。幂等、并发版本检查、事务、状态约束、审计与更正记录。
备份旧版包保留、构建产物备份；页面仅备份界面偏好。数据库与附件一致性备份、受控恢复、恢复演练、明确 RPO 和 RTO。

3. 当前前端措施及其实现边界

3.1 动态文本不进入 HTML 解析器

src/core/dom.mjs 的 el()、text() 使用 createElement、createTextNode 和 textContent 构建动态界面。用户输入、表格单元格和错误消息都按文本处理；on*、srcdoc、style 属性不能通过该工具写入。事件通过 addEventListener 注册。

这是一套供内部组件使用的 DOM 构造接口。标签名、属性名和组件结构仍必须由开发者控制；不能把完整的用户对象直接传作属性参数，也不能据此宣称任意 HTML 已被净化。URL、文件、CSS 和富文本属于不同语境，要分别设计校验。文本节点是展示不可信普通文本的合适方式，但并非所有 setAttribute 用法都安全。OWASP：DOM based XSS Prevention Cheat Sheet

文档正文 pages/readme.body.html 是构建时使用的受控静态内容：保留原文 ID、表格和外链，移除脚本、样式标签、行内样式和行内事件。此处理只用于这份受控项目文档，不作为接受任意用户 HTML 的通用净化方案。将来若支持商品富文本，应单独确定允许标签、属性和 URL 的规则，并采用持续维护的净化工具。

3.2 链接与静态资源

safeHref() 允许受限的本地相对路径、受限的锚点，以及不带用户名或密码的 HTTPS 链接；拒绝控制字符、空格、反斜杠、目录回退片段和其他协议。外部新窗口链接设置 noopener noreferrer。

该函数只负责代码实际使用的链接语境；图片来源、下载对象 URL 和将来的后端抓取任务不应共用一条过度宽泛的规则。公开商品页链接与采购来源链接分别建模，避免将内部采购来源误展示给客户。URL 中不得携带会话、密钥或真实附件的长期访问凭证。

3.3 CSP 与发布检查

本次构建采用外置脚本和外置样式，不依赖外部 CDN、eval 或行内脚本。最终 HTML 应带与实际资源一致的 CSP：仅加载本包所需资源，阻止对象嵌入和业务网络连接，禁止表单对外提交；不得为消除报错而直接放宽为 unsafe-inline 或任意来源。CSP 是补充防护，安全 DOM 与字段校验仍需保留。MDN：Content Security Policy

静态 HTML 使用的 CSP meta 不能提供全部响应头能力。尤其是 frame-ancestors 不支持通过 meta 设置，因此本次不能宣称已通过 meta 防止所有页面嵌入。真实部署应在可控的 HTTP 服务端配置 CSP 响应头及合适的 frame-ancestors，并按托管能力检查 HTTPS、内容类型和其他安全响应头。MDN：frame-ancestors

发布验收同时覆盖本地 file:// 打开和 HTTP 静态服务场景。检查是否存在 CSP 报错、失效资源、行内事件、远程字体或脚本；不得仅以源码中的策略字符串判断最终页面已通过验收。

3.4 查询、共享状态与页面释放

src/core/router.mjs 仅接受导航登记的路由；解码失败或未知 ID 返回可恢复错误。src/core/async-task.mjs 同时采用 AbortController 和递增任务序号，避免过期请求结果覆盖新状态。onSearch() 采用 160ms 去抖，并处理中文输入法组合事件；页面释放时取消尚未触发的查询。

共享状态通过明确的状态容器和动作更新，业务视图不得直接改写其他模块的状态。列表只更新结果区域，保留当前输入节点和焦点；每页默认 10 条，最大 50 条。加载、空结果、失败与正常状态分别呈现。这些措施主要防止竞态、误展示和资源泄漏，不能当作身份授权或业务事务。

3.5 localStorage 只保存低敏偏好

src/services/preferences-storage.mjs 将界面偏好放在版本化键 zhenpu.preview.v2.1.1.ui。偏好通过统一校验器读取和保存；浏览器拒绝存储、空间不足或已保存内容无效时，页面返回可理解的提示，并使用当前内存状态或默认布局。

这不是加密存储。能够在同源页面执行的脚本可以访问相应浏览器存储，存储内容也必须视作可被修改的输入。真实订单、联系人、供应商成本、密码和会话凭证不应顺手加入此偏好对象；浏览器存储也不能证明某人属于某家公司。OWASP：HTML5 Security Cheat Sheet

3.7 CSV 与下载

src/services/downloads.mjs 仅导出当前允许的列和值，最多 5,000 行、UTF-8 内容最多 5 MiB。字段统一加双引号并转义内部双引号，使用 BOM 和 CRLF；对可能被解释为公式的起始内容做文本化处理。下载文件名替换路径分隔符与不允许字符，并限制长度；临时对象 URL 在下载触发后释放。

CSV 是文本交换格式，接收软件可能将某些内容解释为公式。公式前缀、制表符、换行和全角字符应列入验收用例；引号和文本前缀不是对所有电子表格行为的绝对保证，用户另存并重新打开文件也可能改变转义效果。未来若导出真实业务且需要可靠的数字、文本类型，应评估带明确单元格类型的表格文件格式，同时仍对字段和权限做检查。OWASP：CSV Injection

浏览器下载只触发保存流程，网页不能据此确认用户最终保存的位置或声称已经原子覆盖磁盘文件。界面应显示“已发起下载”等符合事实的结果；下载列表 CSV 不能代替可恢复的数据库备份。

4. 真实业务后端必须补齐的能力

以下是接入真实业务前的实现要求，不是本次静态包已有功能。它们不决定未确认的价格、利润、账期或 A/B 业务规则；原需求中的 R/D 问题继续保留。

4.1 公司隔离、账号与最小数据接口

身份验证完成后，服务端从会话解析公司和账号，不信任客户端自行提交的 companyId、角色或数据范围。查询订单、修改收货组、上传发票、下载附件、批量导出等操作均需同时验证账号状态、公司归属、对象归属与操作权限。猜到订单 ID 或取得文件地址不能获得访问权。

客户接口只返回客户所需字段，采购成本、供应商资料和内部备注在服务端投影阶段排除。管理端权限进一步区分查看成本、修改价格、维护客户资料、导出与恢复；不能以“能打开后台”作为所有操作的授权。

未来主账号与子账号功能启用后，提交者、审批者和公司归属分别记录；必须由服务端执行“子账号业务经主账号审核提交”的规则。用户名每年可改一次、公司名称固定等限制也应以服务端记录和时间为准，不能由浏览器日期或可修改字段决定。OWASP：Authorization Cheat Sheet

4.2 会话、CSRF 与接口变更

真实系统若使用 Cookie 会话，应设置合适的 HttpOnly、Secure、SameSite 属性，提供登录后会话更新、退出撤销和过期处理；具体有效期与登录策略在账号设计时确定。状态变更使用合适的 HTTP 方法，不能用 GET 链接执行采购确认、资料删除或发票替换。

Cookie 认证的写接口应采用服务端验证的 CSRF 防护方案，并结合来源校验。SameSite 是补充措施，不能在所有部署场景下直接替代 CSRF 令牌或等效验证。CORS 配置也不替代用户或对象授权。当前静态包没有认证会话或业务写接口，因此不宣称实现了服务端 CSRF 防护。OWASP：CSRF Prevention Cheat Sheet

4.3 订单一致性、幂等与更正

订单、购物袋、收货组、采购明细和发票分别具有稳定 ID。提交整单、确认收货、变更价格、录入实际结算结果等服务端动作使用幂等标识，避免双击或重试产生重复业务。涉及多个记录的更新在事务中完成；并发修改通过版本号或等效条件检查处理，冲突时要求重新核对，不能静默覆盖。

履约状态、票据状态和结算资料状态分别保存。缺少采购成本要显示资料待补，不能自动按零计利润；尚未确认的利润口径不得由开发自行选择。已确认业务的修正记录修改人、时间、原因和关联版本；不通过直接删除历史记录掩盖更正。

“一个订单一张客户发票”的约束应在发票关联和有效状态上保持一致。将来若需要作废、红冲或重开，应保留历史关联并另行确认流程，不在当前版本擅自决定票据处理规则。

4.4 私有附件、发票上传与 OCR

真实附件放入私有存储，业务记录只保存受控的附件标识；下载时检查公司、订单与当前账号权限，再短时授权访问。随机文件名只减少猜测，不替代权限检查。公开商品主图与私有发票、合同、签收附件采用不同的访问策略。

上传链路在服务端验证允许的扩展名、实际类型、文件内容、数量和大小；不能仅信任浏览器传入的 MIME 类型。采用服务端生成的存储名，保留原文件名供安全展示；文件不放到可执行路径。按允许类型配置恶意内容扫描或必要的内容处理，压缩文件与复杂文档需额外评估解压和解析资源限制。上传授权、处理超时、失败回收也属于该模块。OWASP：File Upload Cheat Sheet

OCR 是辅助提取：结果显示识别来源与待核对状态，不因识别成功自动确认发票真实、金额正确或订单归属正确。识别服务如需向第三方发送文件，应先明确发送范围、留存和删除方式；密钥保存在服务端。用户仍可按订单手动上传并核对必要信息，识别失败不得阻断这一路径。

4.5 外部商品链接与物流服务

商品链接作为普通文本记录时，前端只提供安全展示。将来服务端主动读取京东、淘宝或其他 URL 时，应单独设计抓取任务边界：明确允许的来源、跳转复核、目标地址限制、超时、响应大小、频率与失败回退。不能让用户提交的任意 URL 直接成为具有内网访问能力的请求。

物流查询与价格更新经服务端适配器调用，API 密钥不得打包进 JavaScript。缓存、查询频率和费用限制以选用服务的届时合同及文档为准；本次不把旧资料中的免费额度视为长期承诺。自行配送没有快递单号和承运商轨迹，不生成虚构的第三方物流信息。

4.6 审计与敏感日志

后端审计至少覆盖登录结果、权限拒绝、价格变更、订单关键状态变化、发票关联、更正、导出与恢复。记录账号、公司、对象、动作、结果、时间与关联请求标识；对必要变更保留前后值或受控摘要。审计日志的查询和导出同样受权限约束。

不把密码、会话令牌、API 密钥、完整附件、完整请求体或不必要的联系人信息写入日志。外部文本按结构化格式记录并限制长度，避免换行伪造日志。日志应有受限写入、保留和访问策略；仅在页面上显示一张“审计日志”表，不能证明后端日志完整且不可篡改。OWASP：Logging Cheat Sheet

5. 三类备份分别负责什么

5.1 发布产物备份：本次构建流程

保留已接受的 V2.1 包。本次源码使用单独版本目录，构建先生成临时产物并校验相对链接、必需文件、脚本和资源，再提交为可发布目录；已存在的产物先备份。失败时保留或回退到上一个可用产物，不把半成品当作新版本交付。执行命令、实际目录和保留策略见 README 与 DESIGN。

这项备份保存站点代码和静态文档。它不保存浏览器里未导出的个人偏好，也不包含不存在的业务数据库。备份包与源代码包不能因为内部有演示“后台”就被误认为已经有生产访问保护。

5.2 界面偏好备份：本次浏览器能力

页面备份只导出第 3.6 节的格式，导入也只恢复三项界面偏好。恢复前校验并展示内容，应用失败保持原状态；撤回只针对当前会话中最近一次应用的内存快照。文件损坏、格式版本未知、字段越界或过大时拒绝应用。

界面偏好文件不带加密和签名，也不需要用它承载敏感数据。浏览器导出后由用户保存；清理浏览器数据、换设备或使用不同来源打开页面时，应通过手动导出的文件恢复，而不是假定浏览器存储永远存在。

5.3 业务备份：未来后端建设

业务备份需要覆盖数据库、私有附件、必要配置和可恢复的软件版本，并记录它们的同一恢复点或一致性清单。单独导出订单 CSV 不能恢复附件关联、状态历史、权限和完整约束。

建议后端设计包含：自动执行与失败告警、完整性校验、独立存放和加密、备份访问授权、约定的保留与删除策略，以及可重复的恢复流程。加密密钥的保管与恢复路径应独立设计，避免备份存在却无法解密。以上为待实施方案，具体存储、频率、份数与费用在部署方式明确后确定。

恢复时先在隔离环境校验备份，核对数据库、附件数量和关联、关键业务状态及账户权限，再执行受控切换。需要避免恢复历史任务后重复触发通知、外部抓取或其他副作用；恢复结果写入审计，并保留可退回的切换点。

目标需要确认的业务含义当前状态
RPO，恢复点目标故障后数据需要恢复到哪个时间点；据此确定可接受的数据回退范围与备份频率。待确认，未设置数值。

6. 验收用例与证据要求

本表是验收标准，不等同于每项已经执行通过。实际执行结果应记录在随包测试报告；尚未连接真实后端的项目，只能审查设计，不能伪造运行结果。

范围应验证的情形通过标准
动态渲染输入 <img src=x onerror=alert(1)>、引号、尖括号和中文。按文字显示；没有创建攻击者指定的标签或触发脚本。
链接javascript:、data:、控制字符、反斜杠、目录回退、带凭证的 HTTPS 地址。不生成可点击危险链接；合法站内链接和允许的 HTTPS 外链仍正常。
路由未登记 ID、错误百分号编码、刷新深链接。显示可恢复错误或正常页，不崩溃、不误渲染路由文本。
查询竞态快速切换筛选、跳页、切换路由、模拟较慢响应。旧任务不能覆盖新页面；离页后不继续更新已释放组件。
输入体验中文组合输入、清空查询、搜索后翻页。输入焦点和组合状态保留；结果和页码一致。
偏好解析无效 JSON、缺字段、错误类型、未来版本、未知键、特殊原型键、超过 16 KiB。完整拒绝，旧偏好不变；错误可理解。
本地存储读取被拒绝、配额不足、已有内容损坏。页面仍能打开，正确提示是否持久化成功。
CSV双引号、逗号、换行、公式前缀、前置空白、全角前缀、数量与大小超限。合法文本完整导出；危险前缀按规则文本化；越界导出拒绝并提示。
数据分包检查客户入口依赖和最终客户脚本；检查公开商品 DTO。不包含后台成本、内部来源与备注样例；明确静态分包不等于鉴权。
CSP 与相对链接本地打开、HTTP 打开、各入口互跳、查看控制台与请求。页面资源正常；没有意外业务网络请求、CSP 放宽或缺失资源。
构建恢复已有产物时重建；模拟生成或校验失败。旧产物有备份或保持可用，不留下被误认为正式版的半成品。
后端权限将来用公司 A 账号请求公司 B 订单、附件和导出。服务端拒绝，且不泄露对象内容；前端按钮隐藏不算通过。
业务恢复将来恢复数据库与附件快照，核对关键业务关系。在约定 RPO/RTO 内恢复到可核对状态；不重复执行历史外部任务。

7. 后续需要确认的安全与运维问题

这些问题只补充实现条件，不取代原业务待确认列表。

  1. 真实系统的部署方式、托管主体与附件存储位置是什么？谁负责证书、更新和故障处理？
  2. 管理端和客户账号采用哪种登录方式？账号停用、人员变更和会话撤销由谁处理？
  3. 发票、合同、图片允许的类型、大小和保留期限分别是什么？是否允许外部 OCR 服务处理？
  4. 哪些角色可以看采购成本、导出客户资料、替换发票或执行恢复？是否需要额外复核？
  5. 可接受的数据回退范围和恢复时长是什么？相应的备份频率、保留份数与预算是多少？
  6. 后端恢复、更正和权限变更由谁操作，谁核对？恢复后如何通知受影响的使用者？

以上未回答前，可以继续完成静态 UI、文档和模块开发；真实业务上线前应落实相应边界并验证。
